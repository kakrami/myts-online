# Fresh reporting contract

The original Settings → Reports flow and four reports remain. The Schedule report covers all scheduled events in the selected team-season, including practices, other events and explicitly cancelled events. Season, Players and Attendance share the canonical completed included-game selection and the June inclusion/rule precedence used by the analysis read model. Attendance reports state this scope. Unknown responses and conflicting responses are separate; absent source data does not become No Response or a zero percentage. Player figures retain null unavailable metrics and an explicit analysis coverage column.

`ReportingService.create(selection,{type,sort,direction})` prepares a full SQL rowset and stores its count, selection, column contract, stable order and content revision. Independent, nonrecurring export-stage jobs copy at most 100 rows per transaction. Every copy and publication checks the original team content revision in the same transaction as the job lease fence. A changed revision fails the capture visibly. A ready snapshot consists entirely of persisted immutable `report_rows`; no live source joins run while paging or exporting it. A preview contains no partial rows while capture is unfinished.

The signed preview cursor is bound to the immutable snapshot and team scope. Full totals do not depend on the first page. Sorting creates a new complete snapshot; it never sorts just the currently displayed page. A correction or source update after publication leaves the viewed snapshot unchanged. Preparing the report again captures current data. Snapshots expire after 24 hours and bounded maintenance removes their rows, exports, binary parts and background jobs.

Excel export is a genuine Open XML ZIP workbook. Strings use inline string cells, numeric scalars use numeric cells, and strings beginning with formula characters remain strings. PDF export writes actual paginated PDF bytes and embeds the licensed bundled DejaVu Sans font. Font metrics are generated metadata; runtime does not parse the full TTF. All cell text wraps; unsupported font characters or cells taller than a page produce an explicit failure rather than blank glyphs or truncated text. Excel remains available for those values.

Both encoders resume from persistent checkpoints and append bounded immutable binary parts. No encoder reads all source data or every report row into one invocation. Files are capped explicitly at 64 MiB; exceeding that bound is a visible capacity failure, never a shortened successful download. Download streaming reads up to 64 × 64 KB parts per query; the largest permitted file needs at most 17 part queries. Report preparation/export jobs use lower priority than fresh schedule collection and remain independent of source authentication failures. The server job runtime continues work after the browser closes; browser polling only updates presentation.

Owners can use all reports. Viewer links need the explicit `reports` category and can prepare/download only whitelisted scalar reports for their one team. Snapshot and export scope are checked before returning rows or file bytes; another team's IDs are rejected. Viewer report generation is a narrowly authorized derivation of a read-only projection, with same-origin protection for creation commands. It does not authorize Coach, raw source observations, account credentials, dataset/evidence files or imports. Owner report files use the same safe projection columns.

Snapshot and export root creation check team lifecycle inside the actual INSERT, in addition to read authorization. A deletion marker inserted after preparatory reads prevents new artifact rows. Explicit viewer mode takes precedence over an owner cookie, including report category and cross-team checks.

Native D1 tests cover more than one hundred rows, stable descending preview/file order, immutable data after corrections, capture invalidation, stale lease rejection, full four-report compilation, null unavailable statistics, viewer/team/category exclusions, deletion between pre-read and creation, and bounded database use. The generated 237-row XLSX was opened with openpyxl; the corresponding ten-page PDF was parsed with PyPDF and rendered with Poppler. Text extraction confirmed Unicode names and the first/last selected rows. These local fixtures do not prove production alarms or real provider authorization; those require separate integrated verification.
