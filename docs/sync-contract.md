# Fresh myTS sync engine

Status: integrated into the fresh review Worker and tested locally with native D1, SQLite Durable Object alarms, and scheduled events. Production deployment and live source acceptance remain separate checks. It does not read old job tables or snapshots.

## Exact integration boundary

`src/sync/schema.js` exports `SYNC_SCHEMA` and `installSyncSchema(db)`. Install after the fresh domain schema because foreign keys refer to `provider_accounts`, `app_teams`, and `team_read_state`.

The domain account contract is `provider_accounts(id,provider,generation,active)`. Private jobs include the account ID and the authorization generation. TeamSnap and Trace cannot enqueue public account work. Credentials remain in the security module; no job stores a password, token, cookie, email code, or credential envelope.

`new JobCoordinator(db, options)` provides:

| Method | Contract |
|---|---|
| `enqueue(spec, subscribers)` | Deduplicates provider + account scope + component + scope + resource key. Returns an opaque job ID. Repeated demand does not reset a saved checkpoint. A changed input, new account generation, or previously disabled job invalidates the old lease and restarts the scan. |
| `enqueueMany(specs,subscribers,{refresh})` | Enqueues at most 32 root demands with set-based writes. Refresh resets finished work and retains an active running lease. Five TeamSnap attachment roots fit the native request budget. |
| `claim()` | One transaction claims a due demanded job and advances every affected team/account status revision. Returns its token, job generation, account generation, scan ID, parsed `args`, and parsed `checkpoint`. Expired crashed leases resume their saved checkpoint. |
| `commit(lease, result)` | One native D1 transaction saves fenced statements, checkpoint, child work, coverage, and revisions. A stale lease/account returns `{state:'lease_lost',committed:false}` and saves nothing. |
| `fail(lease,error)` | Classifies temporary, blocked, and permanent failures. Keeps saved rows/checkpoint/coverage. Updates the complete team's status revision and emits a sanitized message. |
| `retry(jobId)` | Explicit recovery preserves the checkpoint. Account authorization must currently be active and valid. |
| `unsubscribe(kind,key)` | Removes this demand from every descendant. Public shared work keeps running for remaining subscribers. Last-demand removal invalidates an in-flight lease. |
| `deactivateAccount(id)` | Invalidates account jobs after the domain account has been disabled. Saved source records remain. |
| `restartAccount(id)` | Uses the newly active domain authorization generation, invalidates previous leases, and starts fresh scans. Call after successful reauthentication. |
| `nextWake()` | Calculates the earliest due job or running lease expiry across the full demanded queue. |
| `status(teamId,{includeExports:false})` | Indexed SQL aggregates cover every demanded source/projection/analysis job by stage, state, and coverage. Owner-only export work is excluded by default. Returns canonical content revision, status revision, and pending projection state. |
| `accountStatus(accountId)` | Full private-account demand totals and distinct catalog/status revisions, so discovery failures invalidate the account chooser even before a team exists. Owner authorization belongs to the API boundary. |
| `runOne(collector,context)` | Claims one job, invokes the injected collector, commits one bounded page or records failure. |

A job spec is `{provider, accountId?, accountGeneration?, component, stage?, scope, resourceKey, args?, priority?, nextAt?, intervalMs?, recurring?}`. `stage` is `source`, `projection`, `analysis`, `export`, or `maintenance`. `recurring:false` finishes after completion until an explicit changed demand refreshes it; projections, analyses, exports, and deletion use this setting. Public account scope is `public`; private account scope is the account's opaque ID. Priorities are 0–100; recommended current fixture/roster priority is 80, discovery 60, historical analysis 20. Age increases priority every five minutes by default, so historical work eventually competes with fresh work. Do not enqueue a historic analysis before its source game/roster dependency has supplied the required keys.

Subscribers are `{kind:'team',key:attachmentOrBookmarkDemandId,teamId,generation?}` or `{kind:'account',key:accountId}`. Catalog discovery is demanded by an account and writes its catalog revision; it never creates or attaches a visible app team. An explicit app action selects a discovered native team and adds team demand. Removing a team attachment removes that attachment's descendants, without canceling another team or bookmark's public demand.

Root enqueue checks team lifecycle and private account generation inside the native transaction, including both job and subscriber writes. A late artifact enqueue cannot recreate work after team deletion begins. The exact team-deletion maintenance job can be prepared before its deleting marker, but cannot run until the marker exists or be admitted after deletion finishes. A shared source continues for live consumers while child demand skips deleting teams; cleanup does not disable unrelated prepared jobs.

The collector receives `{db,env,lease,args,checkpoint}` and returns:

```js
{
  statements: [{sql, params}],
  checkpoint: { /* bounded native pagination position */ },
  children: [{ /* job spec */, subscriberMode: 'inherit'}],
  complete: false,
  coverage: 'partial',
  retrievedAt: /* actual successful upstream timestamp, or omit */, 
  observations: [ /* sanitized request metadata; no bodies or credentials */ ],
  rowsSaved: 25,
  publishContent: false
}
```

Each SQL descriptor must contain `$FENCE` in its write predicate. `INSERT ... SELECT ... WHERE $FENCE ... ON CONFLICT ...`, `UPDATE ... WHERE $FENCE`, and `DELETE ... WHERE $FENCE` are supported. The engine replaces the placeholder with its own transaction-specific fence. SQL descriptors cannot write engine tables or provider accounts. The application collector is trusted code, not arbitrary user SQL. The source repository must generate every descriptor with the predicate; an unfenced descriptor is rejected before any write.

Children must explicitly choose `subscriberMode:'inherit'` or `'explicit'` with `subscribers:[...]`. Inheritance uses the parent's **current** demand, so a removed attachment is not resurrected by a slow collector. Explicit scope can narrow to a subset of parent demand and cannot grant another team. Private children cannot cross account authorization. The narrowly defined `'projection'` mode only queues a domain projection for a validated pending app-team/season; it cannot grant source/account demand. This allows a shared source change to refresh each independently attached season. Child creation and demand propagation occur in the same transaction as the saved source page and checkpoint.

Source writes advance `status_revision` but do not claim canonical content is published. A projection job may return `publishContent:true`; only this stage advances `content_revision`. Domain projection writes use the same fence, including their input-revision compare-and-set. The domain's projection builder already updates content only when its hash changes, so its dispatcher returns `publishContent:false` to prevent a duplicate counter increment. Analysis completeness is a separate job stage, never inferred from successfully downloading a match summary. `complete:true` finishes this scan; `coverage:'partial'` can still describe incomplete derived facts. Coverage also represents `unpublished`, `restricted`, and `unsupported`; a completed availability check does not imply published analysis. `last_attempt_at`, `last_retrieved_at`, `last_saved_at`, and `last_complete_at` are distinct. Only an actual collector `retrievedAt` (or failure `retrievedAt` after an obtained response) advances retrieval time. Local projection work and a timeout without a response do not invent it. A failure can supply `coverage` only when it has observed that availability state.

`sync_observations` persists at most 16 sanitized observations per page, with job/scan/attempt identity, endpoint without query/authentication, response status, actual retrieval time, bytes, content hash, row count, and safe error code. Persistence and checkpoint advancement share the lease fence. No response payload, request parameter, or credential is stored. Each audited commit deletes at most 500 observations older than fourteen days. Its read API is owner-only.

`ApplicationSyncService` connects source collectors to guarded domain builders. `enqueueDiscovery` stores owned source candidates without creating app teams or importing every team's details. `attachSelected` adds an explicit attachment and independent source roots. Production projection calls `buildProjectionPage`: identity, event, and player rows are staged across bounded pages, then one published pointer advances visible content. Cleanup runs in later pages. A successful pointer publication queues a bounded analysis catalog for that season; the catalog emits at most 32 Trace-linked or explicitly corrected matches per page, with current/recent priority 70 and historical priority 20. Non-Trace seasons without explicit corrections do not enqueue unsupported per-match work. `enqueueAnalysisRefresh` accepts an optional event ID; a season/player correction queues the paged catalog instead of looping through a season in the HTTP request.

`recoverDemand` repairs auth/domain commits interrupted before enqueue: at most two accounts and three pending projections per invocation, reduced further by the remaining statement budget. A source commit queues up to 128 child demands inline; additional affected seasons remain durably pending and are recovered in bounded scheduled pages. Recovery reserves three statements for the caller's retention work. It never performs unbounded startup recovery.

`TeamLifecycleService.beginDelete(teamId,{revision})` prepares a maintenance job and atomically marks the team unavailable when the profile revision matches. The HTTP boundary requires the current nonnegative revision; stale requests return 409, and repeated requests for an already deleting team are idempotent. Preparation before marking closes the enqueue crash window: an unmarked team cannot run deletion. A lifecycle marker immediately denies team reads and fences conflicting publications. The maintenance job removes local demand and drains team-local coaching, analyses, reports, data files, projection rows, attachments, settings, and seasons in bounded pages. Binary parts use smaller 64-row chunks. Shared provider accounts, native facts, global correspondence identities, shared club branding, and other teams remain. The final page removes the app team and leaves an explicit deleted lifecycle audit record. The maintenance job never deletes its own commit fence.

## Background execution and bounds

`createSyncRuntime(collector)` exports a native SQLite Durable Object class. Wire it as the `SyncRuntime` export, bind `SYNC`, and call `wakeSync(env)` after the ordinary connection/enqueue command. `scheduledSync(controller,env,ctx)` is the scheduled-event fallback. Status and data GET requests do not run jobs.

The runtime persists a recovery alarm **before** source work starts. It rearms from D1's complete due queue after each page, replacing its temporary recovery alarm with the actual next due time. If a successfully committed page uses all 48 statements, it directly schedules a short alarm and defers the due-queue read to the next bounded invocation. It does not misreport the already saved source page as failed or wait for runtime recovery. A persisted wake sequence prevents a concurrent enqueue from being lost while the runner reads its due queue; an expired crashed lease cannot require an open browser. The runtime records its failure in Durable Object storage and rearms on an execution error. A failed or blocked source does not suppress independent demanded work.

Default lease duration is 45 seconds and page alarm delay is 500 ms. Collector transport must enforce its own timeout below the lease duration. Temporary failures retry exponentially from one minute up to six hours; a longer upstream Retry-After is honored. Blocked/permanent failures wait for explicit recovery. Transient failure messages never include response bodies or credentials.

Each invocation has a 48-statement `BudgetDB`, measuring native D1 statements and rows read/written. A source page may have at most 32 set-based SQL descriptors, 128 children, 8 KiB arguments/checkpoint, 256 KiB child demand, and 2 MB total bound values. Commit checks the **remaining** invocation budget before the first source write. Collectors must reserve the known whole page cost before doing optional database reads and split work into smaller pages when necessary. A budget rejection is a retry with no falsely saved checkpoint. There is no record-per-statement roster/fixture loop or monolithic saved-team snapshot.

## Evidence and limits

`TeamCatalog` keeps teams, seasons, and attachments bounded with separately signed continuations. `/api/teams` defaults to 50 teams; `/api/teams/:id/seasons` defaults to 25 seasons; attachment catalogs default to 100 attachments. Every response carries `items`, `total`, `revision`, and `next_cursor`; authorized preferred teams/seasons are returned separately even outside the current page. Bootstrap exposes the seed pages and `team_catalog`, `season_catalog`, `selected_team`, `selected_season`, and `selection`. It does not silently truncate the selected context. Typed catalog counters track structure, labels, lifecycle, and attachment authorization independently of source statistics, so ordinary background collection does not invalidate an otherwise stable chooser cursor. Season reads are owner or exact-team viewer scoped; attachment catalogs remain owner-only. An explicit viewer header takes priority over an owner cookie and an invalid viewer link cannot fall through to owner access.

`tests/team-catalog.test.js` exhaustively reads 103 teams, 106 seasons, and 151 attachments through native D1 bounded pages, proves off-page selected pins in bootstrap, scope-bound cursors, catalog-only revision restart, viewer precedence, and deletion visibility. Each catalog invocation stays within seven SQL statements and bootstrap stays below the 48-statement budget.

Team catalog rows include `club_id`, `logo_revision`, `owner_logo_available`, and a grounded provider `logo_url` of at most 2 KiB. Shared uploaded images are fetched once through the actor-scoped `/api/teams/:id/logo` endpoint and are never repeated across catalog rows. Its DTO is `{team_id,club_id,revision,logo,source}`; a single image is bounded by 128 KiB. Manual club branding takes precedence and a cleared override returns the verified provider default. `branding_revision` changes independently from the sorted catalog revision, so an image edit updates image references without restarting an otherwise valid team continuation. Native tests load fifty references to one near-limit upload in a catalog response below 32 KiB, verify shared owner image reads and viewer/lifecycle scope, reject unsupported external URLs, and preserve explicit ambiguity for conflicting provider defaults.

`node --test tests/sync-workflow.test.js` exercises native Miniflare D1 and SQLite Durable Objects. Its alarm test starts one ordinary enqueue+wake action, then makes no browser or manual runner requests. Seventy-four child jobs and the parent save 148 source pages: 74 ready jobs, one deliberate human-verification blocker, and one transient job that recovers. Tests shorten alarm delays to 2 ms and use source-like fake pages; they do not claim real provider authentication or Cloudflare production timing.

Additional native tests cover shared identity/account scope, explicit discovery without app-team creation, crash-before-save via lease expiry, rejected stale workers and reconnect generations, source-page rollback, typed-source to canonical-projection integration with stale-input rollback/recovery, child scope narrowing, partial coverage under failure, more than 40 job status totals, separate projection publication, exponential backoff, aging, unlink/reattach, concurrent claims, and budget rejection/recovery.

`tests/application-sync.test.js` uses the real TeamSnap collector and encrypted credentials against synthetic Collection+JSON responses. An ordinary discovery action finds 21 native candidates without visible teams. Explicitly selecting one team imports 151 events across resumable source and projection pages; later upstream title/time changes publish while the browser stays closed. Six statement slots are reserved for API inspection/owner/profile overhead. A public source shared by 131 seasons queues 126 projections inline alongside its two source children; two native scheduled events recover the remaining five, and native alarms publish all seasons without browser or manual runner requests. Separate recovery and diagnostic retention tests cover interrupted enqueue, owner-only metadata, retention caps, unsafe audit rejection, and stale-lease fencing. This proves synthetic provider contracts and local native alarms, not live TeamSnap final scores or production access.

`tests/team-lifecycle.test.js` proves native alarm-driven deletion across the complete fresh schemas: 251 coaching rows, 251 frozen report rows, and 251 binary parts drain across bounded maintenance pages while a second team, shared provider facts, account, and club branding survive. An in-flight projection cannot commit after deletion starts. Lease expiry resumes cleanup with its saved checkpoint; stale revision rejection leaves the team visible and cannot activate the prepared deletion job. A separate exact-48-statement alarm regression proves checkpointed pages continue without a fictitious runtime failure or sixty-second recovery delay. Track correction queue tests reject another team, wrong account generation, and wrong match side before creating private demand.

A hard Workerd process kill is not simulated. Actual Cloudflare alarm/cron timing, provider changes, and live private source import are separate deployment gates; tests against the older live build cannot prove this fresh engine is deployed. Original UI and complete assembled API checks are tracked by the parent review workflow.
