# myTS rebuild acceptance baseline

## Scope and evidence

The user-facing baseline is **6.20.133**, not the redesigned 7.0.1 interface. Keep its features, compact layout, navigation, detail sheets, controls, and mobile interactions. Change an existing flow only when required to correct a documented defect. Reimplement the contracts below against a fresh schema; do not copy the old storage architecture, migration code, or compatibility readers.

Source references use function names because the original frontend is embedded in a large generated string in `release-inspection/source/worker.js` (**O**). Original release limitations and Coach behavior also appear in `release-inspection/source/README.md` (**OR**). **N**, **R**, and **A** refer to historical 7.0.1 review paths (`web/app.js`, `src/routes/`, `src/auth.js`), which are removed from this rebuilt project. These historical code observations describe the baseline problems, not the final runtime or a claim that every original workflow was correct in production.

Every acceptance check below is a **required gate for the rebuilt release**. Missing original workflows are **must-restore requirements**, not optional enhancements. A different implementation is allowed underneath the interface; silently removing a feature is not. Each gate remains pending until recorded against the final packaged build. Existing local or simulated passes do not establish live provider or production completion.

## Results to record before release

For each gate, record the build/ZIP hash, environment, provider/account or synthetic fixture, steps, expected result, actual result, and evidence. Use separate labels: **code reviewed**, **local simulated pass**, **local real-source pass**, **production pass**, **failed**, **blocked/unverified**. A missing API or UI workflow is a failure, not a skipped test. A provider sign-in or verification wall is reported as blocked; it does not prove an app defect or a successful integration.

Known 7.0.1 evidence: local API reproductions demonstrate duplicate logical teams, duplicate linked roster rows, and 74 relevant jobs behind a 40-job status page. Prior real public GotSport checks used local native D1 with Node HTTPS, not Cloudflare egress. Prior mobile/native-runtime tests used synthetic account/provider data. Live TeamSnap/Trace authentication and the final production browser-closed workflow remain unverified. The rebuilt release must rerun relevant gates against its own final artifacts.

The release is accepted only when the preserved frontend workflows and corrected data/jobs pass together. Record every remaining limitation explicitly; do not call the build complete based on module tests, screenshots, or a health response alone.
