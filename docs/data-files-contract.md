# Current source datasets and evidence

Settings → Data files operates on one explicit app team and season. These owner-only operations never export owner sessions, provider credentials, Coach material or deployment settings. Viewer links cannot read, create or import these files.

The stored ZIP contains ordered `segments/000000.json` entries and a final `manifest.json`. The manifest identifies `myts-source-dataset` or `myts-source-evidence`, format `7.1`, the exact current release, selected season, attached native source teams, portable private-account labels, source revision, creation time and each segment’s SHA-256 checksum. ZIP CRC checks protect every entry. Evidence files are for inspection; imports accept source datasets from the exact release only. There are no compatibility readers or migrations.

Every export captures the complete selected source rowset, including typed public competitions, divisions, standings, roster and schedule observations and authorized private attendance, logistics, Trace member, clip, tracking, statistics and heatmap observations. Sections are split by public or individual private account scope. Canonical approvals, corrections, credentials and live entitlement proofs are excluded from the imported source model. Exported account labels replace installation account UUIDs. Recursive token, password, credential and session fields are redacted.

Capture runs as a resumable background job. Each invocation serializes at most ten ordered source rows; large rows reduce the segment length. SQL and binding dictionaries keep checkpoint metadata compact. A change to the selected serialized source graph, season, attachments or provider-account generation during capture produces a visible failure; unrelated source ingestion and projection publication do not invalidate the capture. A monotonic row-version registry and exact scoped count/max signatures include public-division opponents, private joined logistics and heatmaps, and coverage scan metadata. The descriptor is checked before and after preparation, then creation compares that signature atomically. Each publication transaction checks the complete scoped dependency signature once, admits a unique token, and requires that token for every stored part, directory entry and checkpoint; incomplete ZIPs are never downloadable. Once the manifest closes, ZIP directory construction and downloads use the immutable saved segments. Closing the browser does not stop processing.

The mobile upload reader reads bounded ZIP slices, validates its directory, expected filenames and entry checksums, and uploads one verified segment at a time. It accepts only the uncompressed ZIP layout written by this release. The browser must stay open until all segments finish uploading. The server stores staged segments without changing source facts. Only the explicit commit starts the background import; it then continues with the browser closed.

Import requires the same selected season and existing explicit source attachments. Private account labels must resolve to active verified native accounts. Every segment is validated before staging and again before applying. An atomic domain precondition prevents source writes and checkpoint progress if an account generation, attachment or team lifecycle changes. Source writes use the job’s current lease fence. File records carry `file_import` provenance, cannot replace live provider observations, cannot grant provider ownership or prove cross-provider identity, and cannot replace approved canonical identities or corrections. A subsequent real provider refresh supersedes file provenance. Future observation timestamps are rejected. Final canonical projection is a separate resumable job.

Capacity limits are explicit: ZIPs at most 64 MiB; manifests and individual segments at most 768,000 bytes; at most 4,096 segments, ten rows per segment, 32 attached native teams and 16 private accounts. Files expire after 24 hours. Capacity failures do not silently truncate records. Team deletion immediately blocks file reads and publications, then removes team-local artifacts while preserving shared source facts.

Export/import root creation, staged segment insertion, received counters and commit state changes all check team lifecycle in their actual atomic writes. Native races insert a deletion marker after validation and prove that delayed requests cannot add artifact rows, stage segments or queue an import. An explicit viewer key rejects these owner-only endpoints even when an owner cookie is present.

The native D1 file suites passed 17 cases: nine isolated scoped-capture regressions and eight complete file workflows. They cover unrelated source/projection independence, own and public-opponent source changes, metadata-only coverage writes, attachment/account generation changes, preparation/publication races, complete 157-row export, browser and Python ZIP checksum validation, source-change failure, exact version and scope rejection, corrupt staging without writes, full staged import, lease-loss rollback, file provenance, canonical correction preservation and owner-only lifecycle enforcement. Domain tests separately cover private Trace member/tracking/statistics/heatmap round-trip and authorization changes. These are local native-runtime checks, not claims of successful live provider login or production deployment.
